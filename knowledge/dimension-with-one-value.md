# 一個「目前只有一個值」的維度

## 形狀

某個維度（租戶、專案、預測目標、疾病、地區）**目前只有一個值**時，
把它從鍵、查詢、標籤、測試夾具裡省略，寫的當天是對的，
而且省略之後程式**仍然完全正確**。

第二個值出現的那一刻，四種東西同時變錯，而且**沒有一個會報錯**：

1. **「取最新的那一個」** —— 原本唯一，現在變成「最後被重建的那一個」。
2. **跨值比較** —— 拿 A 的分數比 B 的分數。兩個都是合法數字、同一個單位、
   同一個座標軸，印出來的句子跟正確的一模一樣。
3. **聚合遮蔽** —— 健康的那個值遮住失敗的那個（`max`、`avg`、
   `ORDER BY … LIMIT 1`）。
4. **測試夾具** —— 夾具裡只有一個值，所以「查詢漏了這個維度」照樣通過。

第四點最惡劣：**守衛本身也假設只有一個**。它會在第二個值出現時
報一個不存在的失敗（偽陽性，而偽陽性是會被吵贏的那種），
或者更糟——繼續通過。

## 怎麼做

- **夾具裡至少放兩個值。** 只有一個值的夾具無法區分
  「查詢有帶這個維度」與「查詢漏了這個維度」。
- **欄位／維度清單用推導的，不要手打。** 手打的清單在下一次 migration 之後，
  漏掉的正好是最新、最可能有缺陷的那幾欄。
- **決定哪些東西「不帶」這個維度時，把理由寫下來。** 不帶是一個判斷不是遺漏。

## 實例（2026-09-09）

一個公衛預測試點加第二個預測題目（流感，與類流感在倉庫裡是不同資料），
四處同時變錯：訓練腳本取最新特徵集、發布器的比較範圍、發布器的現役查詢
（拿流感 MAE 比類流感 MAE 並回報「維持現役」）、看板的閘門 SQL 與事後評分
（把流感預測對上類流感的實際值，大四倍的數字）。
第五處在守衛裡：no-lookahead 測試拿流感的完整集去比類流感的截斷集，
報出 500 列的「洩漏」——一個不存在的失敗。
