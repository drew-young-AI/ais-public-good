# 回測不是上線分數

## 形狀

模型層的節點通常長這樣，而且很容易全綠：

```
特徵集 ok ／ 回測 ok ／ 上線閘門 ok ／ 已發布預測 ok ／ 排程重訓 ok
```

**這五個都是「模型被使用之前」的事。** 沒有一個回答
「發出去的那個數字，後來對不對」。

實測案例：五節點全綠、閘門確實在拒絕（只有 t+2 過關）、
已發布 2 筆預測——而該系統**從未有一筆預測被評分過**。
`grep` 全 repo，`forecast` 與 `actual/observed/error/score` 同時出現的程式：零筆。

## 為什麼回測填不了這一格

rolling-origin 的 MAE，是拿模型去比**它被擬合圍繞的那段歷史**。
上線分數是拿**真的發出去的數字**，比**真的到來的那一週**。

同一個 pilot 上兩者相差一個數量級：回測說 t+2 只贏持平基準 `+0.55%`，
唯一一筆能評分的實際預測贏了 `30.6%`。**兩個都是真的**，
只是問的不是同一個問題。板面上只有前者時，板面回答的是另一個問題。

## 三個實作時一定會踩的坑

1. **單位。** 預測目標若是**比率**（分子/分母），而事實表存的是計數，
   把計數跨 metric 加總當「實際值」會得到差三個數量級的比較——
   **而那個比較在 SQL 上完全合法**。實際值必須用**建特徵時的同一組分子分母**重算。
2. **扇開。** join 條件少一個維度（地區、就診別），2 筆預測會變成 44 列，
   板面顯示「22/44 勝過持平基準」。**那個字串沒有一處看起來不對**，
   n 還變得比較健康。守衛要用不變量：**評分筆數不可能多於預測表的列數**。
3. **n 很小是設計出來的。** 閘門刻意很少放行，所以樣本天生就少。
   detail 裡必須帶 `n=`，否則 `1/1` 在板面上讀起來像戰績。

## 還沒被評分不等於失敗

t+2 的預測要兩週後才能評分。把「尚未到期」判成紅色，
會做出一個**依設計永遠紅**的節點，而那種紅燈的下場是被關掉。
「已發布但目標期未到」要有自己的一句話。

## 別把資料漂移當成模型漂移

`資料漂移`（今年 vs 去年的資料分布）與
`模型漂移`（模型現在的表現 vs 它上線時的表現）名字像、意思完全不同。
**前者存在，會讓人以為漂移這件事已經顧到了。**
實測中這是唯一逃過跨 session 稽核的項目——被要求過、沒做、也沒登記，
在 repo 裡長得跟「從來沒被要求過」一模一樣。

模型漂移的**前提**是先有「預測 vs 實際」的歷史。沒有它就建漂移偵測，
偵測到的是雜訊不是漂移。
